# AutoBI - from any CSV / Excel file to a clean model, insights and a Power BI project

Version 2 of the *Credit Card Financial Dashboard*. Instead of one hand-built report for one dataset, this is a
pipeline: give it **any** CSV / TSV / Excel file (or a folder of them) and it

1. **loads and cleans** it (encodings, delimiters, `$1,200` / `12%` / `(300)` numbers, `dd-mm` vs `mm-dd` dates, stray spaces,
   inconsistent capitalisation, duplicates, blanks),
2. **builds a star schema** - appends files that are the same table (and repairs *column-name drift*), detects join keys between
   different tables, picks the fact table, adds `Dim_Date` and age/income bands,
3. **analyses it automatically** - KPIs, breakdowns with significance tests, trend + anomalies + forecast with a back-test,
   correlations, risk drivers (chi-square + gradient boosting with cross-validation), K-means segments, data-quality findings,
   and plain-English insights,
4. **exports** cleaned CSVs, an HTML dashboard, an Excel workbook (native charts) and
5. **generates a Power BI project (.pbip)**: semantic model (Power Query M + relationships + DAX measures + date table)
   and a 4-page report.

```
python run_autobi.py my_data.xlsx                      # one file
python run_autobi.py data_folder -o output/sales       # several files -> one model
python run_autobi.py examples/credit_card -c configs/credit_card.json -n "Credit Card Analytics"
```
Windows: `Run_AutoBI.bat my_data.xlsx` (installs requirements first).

Requirements: Python 3.10+, `pip install -r requirements.txt`.

## Optional config (`-c config.json`)
Everything is auto-detected; override only what you need:
```json
{
  "name": "Credit Card Analytics",
  "date_column": "Week_Start_Date",
  "dayfirst": true,
  "derived": {"Revenue": "Interest_Earned + Annual_Fees"},
  "primary_measure": "Revenue",
  "target": "Delinquent_Acc",
  "fact_table": "credit_card",
  "drop_columns": ["current_year"],
  "table_names": {"credit_card": "Fact_Transactions"},
  "roles": {"Zipcode": "category"}
}
```
`derived` accepts any pandas expression over the fact table's columns. `target: "none"` disables risk analysis.

## How it decides things (so it is explainable)
* **Column roles**: date, id, binary, ordinal (few integer values), numeric (*additive* amounts/counts, *rate*, *attribute* such as
  age/income), category, text, constant. Additive columns are summed, attributes/rates averaged.
* **Appending files**: same columns (≥90% matched by name, or by fuzzy name + same type + comparable scale) -> one table.
* **Relationships**: same-named key, unique on one side, ≥90% of the other side's values present.
* **Significance before storytelling**: group differences use Kruskal-Wallis + eta², risk segments chi-square + Cramér's V,
  trends linear regression p-value, forecasts are back-tested against naive baselines, and the report says when there is *no*
  signal (e.g. weak AUC, weak clusters) instead of inventing a story.

## Tests
`python -m unittest discover -s tests -v` - 20 tests: parsing edge cases, schema-drift repair, KPI reconciliation against the raw
CSVs, a multi-sheet Excel dataset, a deliberately messy latin-1 / semicolon CSV, three real scikit-learn datasets, tiny/degenerate
files, and checks that the validator catches broken output.
`examples/ecommerce_orders.xlsx` and `examples/messy_sales.csv` are **synthetic** fixtures (generated by `tests/make_demo_data.py`).

## Limits
* Power BI Desktop is Windows-only: the generated `.pbip` is validated structurally but could not be opened in Desktop here.
* Forecasting is a simple damped-trend model; clustering/risk models are exploratory, not production scoring.
* Currency is not inferred (numbers are shown unit-less).
* One fact table per run; unrelated tables are loaded but not joined.
